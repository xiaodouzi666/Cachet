# Deploying Cachet for judges

The deployment Blueprint specifies two Docker services on the Singapore Starter plan. The API runs as a single process with SQLite on a 1 GB disk mounted at `/var/data`. Its image includes the source contexts, measured calibration and validated replay recordings. The web image serves Next.js and forwards allowed workspace routes with its own server-side `BFF_TOKEN`. Operator endpoints require the separate `ADMIN_TOKEN`. [Render monorepos](https://render.com/docs/monorepo-support) · [Persistent disk lifecycle](https://render.com/docs/disks)

1. Connect the GitHub repository to the Render workspace. Create the two services from the Blueprint or its equivalent API definitions. When using the API, look up each exact service name before creating it. Compare its repository, branch, root, region, runtime, plan and disk before reusing it. Use the HTTPS origins returned by Render. [Create service](https://api-docs.render.com/reference/create-service)
2. Configure only the service-specific variables in the Blueprint. Keep `RENDER_API_KEY` on the operator machine. Set the sandbox credentials on the API, and the same workspace gateway token on both services. Use an independent production admin token on the API. Configure it as `PRODUCTION_ADMIN_TOKEN` on the GPU heartbeat sender and operator host. Reserve `CACHET_SOAK_TOKEN` for the API and the operator soak runner. Of these service credentials, the Next.js server needs only the browser gateway token. Set `PUBLIC_WEB_URL` to the frontend origin on both services and `CACHET_API_URL` to the API origin on the web service. The Studio browser license is a public build argument. Redeploy each changed service and wait for the live deploy status.
3. Keep the GPU and its tunnel running. Start the GPU heartbeat agent with `.venv/bin/python scripts/gpu_agent.py start`. It registers its current HTTPS endpoint and refreshes it every 30 seconds. Once live health is confirmed, reserve an exclusive GPU window to calibrate the deployed network path before taking financial measurements. The job measures 25 cold/warm pairs and flushes the shared cache. [Registration and calibration](inference-registration.md) Check both the direct health URL and the frontend's `/api/health`.
4. Run `.venv/bin/python scripts/register_webhooks.py --url https://<api-host>/api/webhooks/paypal` on the operator machine. Keep the previous subscription active while configuring the returned ID in the API service's `PAYPAL_WEBHOOK_ID`. After redeploy, verify a signed PayPal sandbox event in the production receiver, recording its event and resource IDs. Retire the previous Cachet webhook subscription only after the new receiver has processed a verified event for the intended production transaction. Match the old ID and URL before removing it. If verification fails, retain the previous subscription and correct the new receiver. A rollback must restore the environment associated with its receiving webhook ID.
5. Use a private journal for the production operator session. Use the same `PRODUCTION_ADMIN_TOKEN` in the operator configuration. Run `.venv/bin/python scripts/seed_demo.py --api https://<api-host> --state logs/production-seed.json --catalog-only`. This uses a dedicated user workspace for public listings, publishes both maintainers' contexts and waits for a fresh hit ratio of at least 95% on each layer. Confirm both rows are hot through the production catalog. Keep journal files and workspace cookies private.
6. For a code rollback, redeploy the last known-good commit to the same services. Keep the existing disk and review schema compatibility before a downgrade. Recheck health, workspace state, mode and webhook delivery after the deploy. [Deploy API](https://api-docs.render.com/reference/create-deploy)

## Verify the active PayPal webhook receiver

`make verify-full` creates sandbox operations and checks signed receiver records against each journal's exact event type and resource ID. A development subscription uses the local receiver's SQLite database. After moving the subscription, keep `PRODUCTION_PAYPAL_WEBHOOK_ID` equal to the active `PAYPAL_WEBHOOK_ID` in the operator's private environment. Bind `PRODUCTION_API_URL` to that receiver's HTTPS API origin and set `PRODUCTION_ADMIN_TOKEN` to its backend operator credential. The verifier queries the backend directly. A provider GET or a successful send from PayPal cannot establish receiver-side signature verification.

To recheck an existing pair of journals without repeating payments, run `.venv/bin/python scripts/register_webhooks.py --check <wallet.json> <payout.json> --wait 180` with the corresponding receiver configuration. Keep pre-migration journals with their original receiver's evidence.

## Budget and storage settings

Keep the API and its background settlement worker in one process on the persistent disk. Read the Blueprint and application defaults together when rotating an existing service. The API uses `CAPTURE_THRESHOLD_USD=2.00`, `FINAL_CAPTURE_MIN_USD=1.00`, `PAYOUT_MIN_USD=0.25` and `JUDGE_PAYOUT_MIN_USD=0.01`. A mandate can span tasks for up to `MANDATE_MAX_AGE_H=72` hours. `RUN_IDLE_END_MIN=10` ends an idle run and preserves the mandate for a subsequent task. Test the browser gateway and the backend against the same disk after redeployment. [Blueprint](../render.yaml) · [Sandbox policy and measured fees](pricing.md)

A clean two-container Compose rehearsal reached all seven checked pages in 104.79 seconds and retained its workspace after both containers were replaced. It ran without GPU or PayPal credentials in Replay. For the hosted deployment, record the verified frontend and API origins, the observed transition from Live to Replay and back, and a provider-signed webhook delivered to that API. ## Optional independent hosted SGLang

Cachet can route a **new** run to a dedicated third-party native SGLang server when the primary GPU is unavailable. The endpoint must provide authenticated HTTPS, the project's pinned Qwen model and tokenizer, native streaming generation with per-request `meta_info.cached_tokens`, and an operator-controlled cache. Configure SGLang with the manifest model ID as both model and tokenizer path, its exact Hugging Face revision, a context window of at least 32,768 tokens and prefix caching enabled. [SGLang native endpoints](https://docs.sglang.io/docs/basic_usage/native_api) · [SGLang 0.5.23 HTTP server](https://github.com/sgl-project/sglang/blob/v0.5.23/python/sglang/srt/entrypoints/http_server.py)

On the Cachet API host, configure `HOSTED_FALLBACK_BASE_URL`, `HOSTED_FALLBACK_API_KEY` and a private persistent path in `HOSTED_FALLBACK_CALIBRATION`. During a maintenance window on this dedicated hosted deployment, run `.venv/bin/python scripts/calibrate_hosted.py`. This flushes its cache 25 times, verifies both licensed source token hashes and measures five cold/warm pairs at each supported length. Rerun after changing the deployment, engine or network path. This procedure consumes actual hosted inference.

Before selecting hosted mode, Cachet checks the origin, model identity and measured calibration. It uses these hosted measurements for SLA and royalty attribution. The global judge flush targets the primary GPU only. A queued run pins its mode and calibration, and an interrupted run retains its committed turns. No automatic replay or second provider call resubmits a partially billed run. Without an eligible hosted deployment, validated recorded workloads remain the fallback. This repository currently has no externally provisioned hosted calibration or independent hosted receipt.

With the primary unavailable and sandbox funding configured, run `.venv/bin/python scripts/e2e_demo.py --smoke --require-mode hosted --state logs/hosted-workspace.json` from the operator host. It requires the hosted health label and ten completed hosted turns before closing and reconciling that workspace.

## Live application verification

The API queues complete live or hosted built-in coding runs for a separate trusted worker. The API never executes the generated code. The worker reads the canonical final answer through an operator-only claim, runs the full HTTP checker inside a network-isolated, read-only, non-root Docker container with resource limits, and returns the receipt. It does not use the GPU or change payment records.

On the Linux operator host with Docker available, keep PUBLIC_API_URL bound to the trusted API origin and the production API's operator credential in PRODUCTION_ADMIN_TOKEN in the private .env. Loopback development uses ADMIN_TOKEN. Build the checker dependency image and start the worker:

```sh
docker build -t cachet-generated-app-check:v2 - < scripts/generated_app.Dockerfile
.venv/bin/python scripts/application_check_worker.py start
```

The worker runs in tmux session cachet-app-checker; its private logs and retry state live in logs/application-checker/. It is separate from cachet-sglang and cachet-gpu-agent, so the full FastAPI check's real 60-second window does not delay inference heartbeats. Keep all three sessions running during judging.

A receipt is tied to the workspace, run, final call, task, turn and exact original-answer SHA-256. The API recomputes those bindings, validates the HTTP evidence and response format, and accepts results only for the worker's current lease. Repeated delivery is idempotent. Infrastructure failures are retried up to three times; stale or unavailable checks remain unverified. The browser polls its owned run's read-only application-check endpoint after generation and shows Checking, Passed or Failed, with inspectable evidence. Neither the browser gateway nor ordinary workspace clients can submit verification results.

Fault follow-ups, operator soak/sponsor jobs, incomplete runs and unsupported tasks are excluded. Replay keeps its separately validated recorded receipts. Existing eligible live runs can be queued by an operator with POST /api/admin/application-checks/enqueue/{run_id}; GET /api/admin/application-checks/{run_id} reads their status. These administrative routes require the existing backend operator token and are not forwarded by the browser gateway. Rechecking does not rewrite the original run-completion event or alter its metering.
